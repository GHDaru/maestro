Contexto Mensageria — o contrato pelo qual uma sessão de agente expõe e consome ferramentas: MCP (Model Context Protocol) para o que ela expõe, e A2A (Agent-to-Agent) para par a par. Fonte da ideia: método — servidor MCP do painel, painel/mcp_painel.py; plataforma: LiteLLM (A2A real).

Identidade de sessão: sempre nome · ref · projeto. O ref muda ao reiniciar — a leitura e a escrita abaixo endereçam por ref.

Por onde a mensagem trafega hoje

O confronto pede o canal real: as três ferramentas MCP não enviam nem leem mensagem — quem carrega a mensagem entre sessões é o harness.

Os canais reais de hoje (exemplo)
canal o que carrega estado hoje
SendMessage / ListAgents (harness) a mensagem entre agentes na mesma máquina, entregue na hora; ListAgents lista quem está vivo. é o canal de hoje (exemplo)
arquivo commitado (fallback) a cópia do [[DONE]] / do handoff, quando a sessão de destino não está viva para receber. fallback real (exemplo)
fila outbox (SQLite) a mensagem endereçada gravada na fila (outbox); os hooks leem e drenam. carrega mensagem (exemplo)
MCP maestro-painel — motivo: as três ferramentas são estado e registro, não uma caixa de mensagens (exemplo) não carrega mensagem (exemplo)

O que a sessão de agente EXPÕE

Servidor MCP maestro-painel — três ferramentas, todas listadas por tools/list (fonte: painel/mcp_painel.py).

As três ferramentas expostas e a política que autoriza cada chamada (exemplo)
ferramenta exposta o que faz regra de política que autoriza a chamada (escopo ferramenta MCP)
estado_atual o estado atual derivado do projeto (equipe, decisões, barra, desvios, riscos); com sessao, o estado daquela sessão. a chamada é regida pela política de escopo ferramenta MCP — a tabela de regras de telas/administracao/politicas.html é a fonte; o protocolo só aponta.
registrar_status registra o status da sessão — só acrescenta; recusa estado fora da lista permitida. mesma política de escopo ferramenta MCP: quem pode chamar registrar_status é uma regra por agente, declarada em telas/administracao/politicas.html.
registrar_peca registra a transição de uma peça; recusado sem a evidência exigida pelo estado (o portão do chamado vira contrato). regra de exemplo da política (escopo ferramenta MCP): ask para Worker, allow para o regente por delegação, deny para sessão de outro projeto — escrita em telas/administracao/politicas.html; a Mensageria não duplica a regra, só aponta para ela.

Quem pode chamar qual ferramenta é política, não protocolo. A autorização por ferramenta (ask / allow / deny) é uma regra de escopo ferramenta MCP na tela de políticas — o protocolo aponta para ela em cada linha acima e não a repete.

Quem autoriza: Chamar estado_atual é leitura — qualquer sessão de agente chama. Registrar status é escrita — autorizada pela sessão dona: ela só acrescenta ao próprio status. Registrar peça é escrita com evidência — autorizada por quem move a peça (a sessão dona da fatia ou o regente por delegação).

A2A — nomeado, não construído

Ligar uma sessão a outra por A2A ainda não existe no Maestro. A tela mostra o que o A2A exibiria e marca tudo como desabilitado — nunca um botão que finge.

Os objetos A2A nomeados, ainda desabilitados (exemplo)
objeto A2A (desabilitado) o que exibiria
— agent card (exemplo) motivo: A2A nomeado, não construído nome · ref · projeto, o estado do agente vivo e as ferramentas que a sessão expõe — a identidade do par.
— pares (exemplo) motivo: A2A nomeado, não construído a lista de sessões com quem esta pode falar, endereçada por ref — hoje inexistente.

Abrir agente / ligar via A2A é ação de regência; aqui só o objeto é nomeado.

A2A por plataforma: A2A tem 5 sim na matriz — a plataforma LiteLLM é uma delas, ao lado das demais linhas sim de protocolos (A2A, MCP); a ideia a copiar, não a dependência.
