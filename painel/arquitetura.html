19 sessões de IA e um humano. O Gilsiley decide (gates, produção, dado pessoal). O Escritório tem 4 sessões no Claude Desktop. Os 2 gerentes e os 13 workers rodam no Claude Code, cada worker numa worktree própria.

Local, dois runners, a banca, o Dev, staging e produção. A máquina local roda as sessões e o painel; o número dela não vale para aprovação. As suítes oficiais rodam nos runners Linux a partir de clone limpo do hash.

Regras de uso

  • runner2 roda uma suíte por vez (3 GB); conferir com pgrep antes.
  • Clone e bundle saem em 24 h; worktree só por git worktree remove.
  • O .env do hindiana é produção: nunca se lê nem se testa contra ele.
  • Dado de produção só vai para destino aprovado (staging, com senhas trocadas).

Rodada local

  • Worker: vitest + tsc na worktree, como pré-checagem.
  • Não conta para APPROVE: Windows não é ambiente de medição.
  • O número que vale é o do runner2, do clone limpo, com git log -1 --oneline.

Do commit do worker até produção, sete validações. Cada uma barra o avanço. A jornada da barra v2 (sessão tutorada de T0 a T5, sem erro de tela nem de servidor) é a validação de produto antes da ordem do humano.
