Cap 01 · [1] · Fundamento

Princípio operacional central

Princípio
IA explora/propõe/escreve; humano especifica/decide/aprova; testes + revisão independente validam.
Mecânica
Accountability ≠ capacidade. O gate humano é ex-ante; o registro é ex-post. Para ação irreversível, a alavanca é a reversibilidade engenheirada.
Conexão
Base de [9] (gates), [3] (rewind), [10] (recuperação).
Política + reversibilidade
# decisão por classe, não por instância
policy: allow | deny | ask

# torna o irreversível reversível
backup · dry-run · staging · soft-delete
Cap 02 · [10] · Fundamento (evidência)

DORA / SPACE

Princípio
Velocidade e estabilidade não são trade-off — os mesmos times são rápidos e estáveis.
Mecânica
As 4 métricas são outcomes de capacidades. Alavanca única: lote pequeno — move as quatro juntas.
Na prática
Bússola qualitativa (lead time, change fail rate). Instrumentar painel = YAGNI agora.
As quatro chaves
throughput
  · deploy frequency
  · lead time (commit→prod)
estabilidade
  · change fail rate
  · time to restore
# capacidades: CI · trunk-based · testes · revisão
Cap 03 · [2] · Mecânica

Spec-Driven Development

Princípio
A spec é a fonte de verdade porque virou o input que gera o código — não a descrição dele.
Mecânica
Valor da spec = ambiguidade × raio × irreversibilidade. Daí as raias. Bug não é spec, é teste que reproduz.
Na prática
Uma ferramenta SDD (Spec Kit); OpenSpec descartado, ideia do delta virou a raia leve.
Fluxo + raias
specify → clarify → plan → tasks → implement

raia leve   bug/typo   → PR é o artefato
raia plena  feature    → specs/NNN
raia infra  migração   → + gates reversib.
Cap 04 · [3] · Mecânica

Fluxo agentic e economia de contexto

Princípio
A janela de contexto é finita e degrada ao encher. O inimigo é o acúmulo, não a falta.
Mecânica
As 4 peças são economia de contexto: o plan comprime, subagentes descarregam, /clear despeja ruído, revisor fresco não contamina.
Conexão
Preserve o load-bearing (a spec); descarte o ruído. Mesma espinha de [2].
O loop
explore → plan → code → commit

subagente   # lê em janela separada
/clear      # reset entre tarefas
reviewer    # contexto fresco, só o diff
Cap 05 · [4] · Mecânica

Orquestração de agentes

Princípio
Map-reduce cognitivo: o reduce (reconciliar as fatias) é do orquestrador, que tem o contexto global.
Mecânica
O corte é mais traiçoeiro que o reduce — vai nas costuras (bounded contexts). Espectro workflow↔agent.
Na prática
Menor autonomia que resolve: workflow por default; agent só quando o corte não é predefinível.
6 padrões (Anthropic)
chaining · routing · parallelization
orchestrator-workers · evaluator-optimizer
autonomous

# no modelo: raias=routing · fluxo=chaining
# revisor=evaluator · orquestrador=humano
Cap 06 · [5] · Estrutura

Papéis e RACI

Princípio
Papéis como modos de trabalho. Preserva-se o contrapeso: decide ≠ executa ≠ verifica.
Mecânica
Delega-se R/C/I; nunca o A (accountability não delega). C sempre independente (contexto fresco).
Na prática
O humano é Accountable pela política, gates e critérios — não por cada item. É o que faz escalar.
Delegabilidade RACI
R  executa    → agente
C  verifica   → agente (fresco)
I  informado  → trace / logs
A  accountable→ humano  # nunca delega
Cap 07 · [6] · Estrutura

Cerimônias e cadência

Princípio
Cerimônia é a função que entrega, não a reunião. Corta-se pela função (daily/planning somem).
Mecânica
Shape Up + Kanban: apetite (tempo fixo, escopo variável) + cooldown. Retro amplificada: erro → regra versionada.
Na prática
WIP limitado pela atenção humana. Paralelize dentro da feature; escale baratear os gates.
Cadência
shaping/spec   # o "planning" real
ciclo (apetite)
checkpoint
cooldown
retro          # → CLAUDE.md / ADR

✗ daily   ✗ sprint planning   ✗ backlog
Cap 08 · [7] · Qualidade

Entregáveis e artefatos

Princípio
Artefato custa duas vezes (escrever + manter). Vive se é input consumido com forcing function — ou imutável (ADR).
Mecânica
"Dar contexto" não distingue; o que distingue é o consumidor e o que quebra se ele envelhece.
Na prática
Não duplicar função já servida: PRD → spec; design doc → plan + ADR. Journey = vivo por gate (P. VII).
Consumidor → forcing function
spec    → agente gera   → código errado
teste   → CI            → vermelho
ADR     → imutável      → não apodrece
journey → gate de PR    → capturas+heurística

PRD / design doc avulsos → YAGNI
Cap 09 · [8] · Qualidade

Definition of Ready / Done

Princípio
Um critério de "done" precisa ser verificável autonomamente (pass/fail que o agente gera e o hook confere).
Mecânica
O trabalho é converter julgamento em check (harness design). DoR = spec executável sem adivinhar.
Limite
Verde ≠ certo: não garante coerência global (ótimo local) nem "a coisa certa" — isso fica com o humano.
Converter julgamento → check
"código limpo"  → lint + fitness fns
"boa UX"        → tokens + heurística
"seguro"        → secret scan + injeção

# fechável por Stop-hook / /goal / /dod
Cap 10 · [9] · Qualidade

Gates humanos e classes de risco

Princípio
Gate uniforme falha sempre: pesado → funil; leve → o irreversível escapa.
Mecânica
Gate proporcional a irreversibilidade × impacto. Automatiza baixo, escala alto, bloqueia lote/admin.
Conexão
Mesmo eixo das raias [2]. Reversibilidade rebaixa a classe → menos gates pesados.
Taxonomia de risco
leitura            → automático
criação reversível → merge
alteração          → aprovação c/ resumo
irreversível       → dupla aprovação
lote / admin       → bloqueado
Cap 11 · [11] · Qualidade

Rastreabilidade

Princípio
Dá o quê + o porquê sem re-derivar. Em solo+IA, os artefatos ligados são a memória que sobrevive ao reset.
Mecânica
Dois sentidos: para frente (cobertura de intenção) e para trás (sintoma→causa = recuperação).
Na prática
Emerge de artefatos se referenciarem; a DoD [8] força o elo. Sem matriz/ferramenta.
O elo
spec NNN ↔ PR ↔ testes ↔ journey

→  spec construída e verificada?
←  bug → código → spec → decisão
   # item obrigatório da DoD
Cap 12 · [12] · Governança

Governança leve

Princípio
Sistema de regras cresce → bloat/ossificação. Força contrária: YAGNI + poda + flexibilidade.
Mecânica
Núcleo firme (constituição) + periferia evoluível (modelo/handbook) + ADR imutável + retro→regra.
Enforcement
Hard gates na máquina (CI) + gates de julgamento no humano (PR template + /dod). Não depende de disciplina.
Aplicação (§12 do modelo)
mecânico  → CI hard gate (testes, fitness,
            changelog) — bloqueia merge
julgamento→ PR template + aprovação humana
agente    → comando /dod (self-check)
