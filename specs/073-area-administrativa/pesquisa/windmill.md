- **O que foi aberto de verdade**:
  - https://www.windmill.dev/ — "Code-first orchestration platform for internal software"; scripts viram "API endpoint and a form" em "20+ languages"; flows são "graphs (DAG)"; workers são "autonomous processes that run one script at a time"; RBAC "Permissions per folder and per group"; "Audit log of every action"; "Self-host on your own infrastructure".
  - https://www.windmill.dev/docs/intro — conceitos iniciais: scripts, "orchestrator for assembling these functions into efficient, low-latency flows", "execution runtime for scalable, low-latency function execution across a worker fleet", "secret management", "robust permissioning".
  - https://www.windmill.dev/docs/core_concepts — índice: "Workers and worker groups", "Concurrency limits", "Job debouncing", "Variables and secrets", "Resources and resource types", "Roles and permissions", "Audit logs", "Groups and folders", "Schedules".
  - https://www.windmill.dev/docs/core_concepts/roles_and_permissions — superadmin / devops / Developer / Operator; "Admin is not a workspace role: it is a flag"; ACLs por item ("Admin (Owner)", Writer, "Viewer: has read-only access"); service accounts; "run on behalf of".
  - https://www.windmill.dev/docs/core_concepts/audit_logs — "logs every operation and action that has side-effects"; filtros "Date, Username, Action (Create, Update, Delete, Execute), and specific Operation"; retenção "365 days" (Enterprise) / "14 days" (Community); export NDJSON em `logs/audit/`; emissão OTel (scope `windmill:audit`).
  - https://www.windmill.dev/docs/core_concepts/variables_and_secrets — "All Variables (not just secrets) are encrypted with a workspace specific symmetric key"; secret backends HashiCorp Vault, Azure Key Vault, AWS Secrets Manager; "Secrets cannot be viewed outside of scripts"; masking; evento de auditoria `variables.decrypt_secret`.
  - https://www.windmill.dev/docs/core_concepts/scheduling — "define Schedules for Scripts and Flows"; "A Schedule consists of a Script or Flow, its arguments, a CRON expression ... and optional Error and Recovery Handlers"; "keeps only one occurrence queued at a time".
  - https://www.windmill.dev/docs/core_concepts/worker_groups — "A worker joins by setting the env variable `WORKER_GROUP=<name>`"; "Queues are named via tags, and Worker groups listen to those tags"; grupos default/native; "Dedicated Workers"; "Autoscaling"; "Pausing ... stops its workers from pulling jobs without stopping them"; compute units ("2 worker-gb-month").
  - https://www.windmill.dev/docs/core_concepts/groups_and_folders — "the privileged method to handle permissions"; folders agregam "scripts, flows, resources, and schedules"; grupos dão "Viewer / Writer / Admin"; instance groups sincronizados por SCIM.
  - https://www.windmill.dev/docs/core_concepts/jobs — jobs são "past, present, or future task executed by a worker"; "queued jobs" ordenados por `scheduled_for`; `priority` 1–100; status "running"/"completed"; cancelamento via API; retries.
  - https://www.windmill.dev/docs/core_concepts/concurrency_limits — limites "for scripts, flows and inline scripts within flows"; parâmetros "Max number of executions within the time window", "Time window in seconds", "Custom concurrency key"; "jobs reach the concurrency limit, they are automatically queued for execution".
  - https://www.windmill.dev/docs/core_concepts/webhooks — "Each script and flow created in Windmill gets autogenerated webhooks"; `/p/u/<user>/<script_name>` e `/h/<hash>`; "Bearer token authentication"; "Webhook specific tokens allow sharing tokens publicly".
  - https://www.windmill.dev/docs/core_concepts/mcp — "an open standard that enables seamless interaction between LLMs and tools like Windmill"; Windmill como servidor MCP (ferramentas para Jobs, Resources, Variables, Schedules, Workers) e como cliente; transporte "HTTP streamable"; gateway `/api/mcp/gateway`.
  - https://www.windmill.dev/docs/core_concepts/ai_agents — AI Agent steps de flow; ferramentas são scripts Windmill; "A tool name must be unique in the step and contain only letters, numbers, and underscores"; MCP servers como ferramentas ("Only HTTP streamable MCP servers are supported"); aninhamento "flow → AI agent → nested AI agent tool" (máx. 2 níveis).

## Observações
- **Documentação apenas**: nada foi instalado nem executado. `docker` não existe nesta máquina e não foi preciso; não há nuvem envolvida. Nenhuma credencial/segredo foi usado (exemplos da doc usam placeholders como `<base_url>`).
- **Pago**: concurrency limits são "Cloud plans and Self-Hosted Enterprise Edition"; autoscaling/alerts e "Dedicated Workers" são Enterprise/Cloud; export de audit logs para object storage e OTel é Enterprise (Enterprise retém "365 days"; Community "14 days"). Self-host é possível ("Self-host in 3 mins", "with Docker or Kubernetes first"). Compliance citado: SOC 2 Type II.
- **Lacunas**: não achei "consumo por agente/sessão/modelo", "caixa de entrada" nem menção a A2A. Não há conceito nativo de "sessão de agente" — o análogo é o conjunto job/worker/worker group. O arquivo `ai_agents` cobre MCP como ferramenta; a página dedicada `/docs/core_concepts/mcp` também foi aberta e confirma MCP (sem A2A).
- Siglas expandidas na primeira ocorrência: RBAC (*Role-Based Access Control*); MCP (*Model Context Protocol*); A2A (*Agent-to-Agent*); CRON (expressão de agendamento); NDJSON (*Newline-Delimited JSON*); OTel (*OpenTelemetry*); SCIM (*System for Cross-domain Identity Management*); UI (*User Interface*).
